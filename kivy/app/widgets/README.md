# Table Widget Architecture

## Проблема
Изначально в файле `table_widget.py` был весь код смешан в одном файле - и универсальная функциональность, и специфическая логика проекта habits. Это делало код непереносимым в другие проекты.

## Решение
Код разделен на три файла с четкой архитектурой:

## 📁 `universal_table.py` - Универсальный код
**Содержит только абстрактную функциональность:**
- `UniversalCell` - базовый класс ячейки
- Универсальные свойства: `text`, `value`, `identifier`, `cell_mode`
- Общие методы: обработка кликов, построение интерфейса
- Абстрактные методы для переопределения в подклассах
- `create_universal_table()` - универсальная функция создания таблиц

**Может быть легко скопирован в любой проект Kivy!**

## 📁 `habits_table.py` - Специфический код проекта
**Содержит только habits-специфическую логику:**
- `HabitsCell` - наследует от `UniversalCell`
- Константы статусов: `STATUS_DONE_MINI`, `STATUS_DONE`, etc.
- Иконки и цвета статусов
- Циклы статусов (0→1→2→3→9→0)
- Интеграция с `HabitsModel`
- `create_habits_table()` - функции для создания таблиц habits

## 📁 `table_widget.py` - Слой совместимости
**Содержит только импорты и переэкспорты:**
- Импортирует из обоих файлов
- Переэкспортирует под старыми именами
- Обеспечивает совместимость с существующим кодом

## Архитектурные принципы

### ✅ Что в универсальном коде:
- Общие свойства и методы
- Абстрактные интерфейсы  
- Обработка кликов
- Создание таблиц
- Ничего специфического для habits

### ✅ Что в специфическом коде:
- Бизнес-логика проекта
- Константы и enum'ы
- Цвета и иконки
- Интеграция с моделями
- Специфические алгоритмы

### ❌ Чего НЕ делается:
- Дублирование кода
- Зависимости универсального кода от проекта
- Смешивание абстрактного и специфического

## Использование

### Для других проектов:
```python
# Скопируйте universal_table.py в свой проект
from universal_table import UniversalCell, create_universal_table

class MyProjectCell(UniversalCell):
    def build_interactive_content(self):
        # Ваша логика
        pass
```

### Для habits (без изменений):
```python
# Все работает как раньше
from .table_widget import UniversalCell, create_universal_table
```

## Результат

- **Модульность**: Четкое разделение ответственности
- **Переносимость**: Универсальный код работает в любом проекте
- **Поддерживаемость**: Изменения в одном месте не влияют на другой
- **Расширяемость**: Легко добавлять новые типы ячеек
- **Совместимость**: Существующий код не нарушен
