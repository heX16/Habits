# Описание проекта Habits Simple Tracker

Проект представляет собой веб-приложение для отслеживания привычек. Пользователи могут создавать привычки, отмечать их выполнение каждый день и видеть прогресс в удобной таблице.

Комментарии в исходном коде - на английском языке.
Все сообщения и строки в проекте - на английском языке.

## Интерфейс главной страницы

### Внешний вид
- Таблица с привычками в строках и датами в столбцах
- Заголовки столбцов содержат дату и день недели
- Текущий день визуально выделен, будущие дни отображаются иначе
- Статусы отображаются эмодзи/иконками в ячейках

### Поведение
- Одиночный клик: циклическое переключение статуса (с ограничениями для `single_checkbox`)
- Двойной клик или клик по специальной кнопке: вызов меню со всеми доступными статусами
- Обновление статуса: мгновенное визуальное, отложенная отправка на сервер (2 секунды)
- Автообновление страницы: в полночь со случайной задержкой
- Привычки с `fail_by_default`: автоматическая пометка проваленными (статус 0 маппируется в статус 9)
- Смещение отображаемой даты: при добавлении параметра `?date=YYYY-MM-DD` в URL, таблица строится от указанной даты
- Быстрый возврат к текущей дате: кнопка "Today" появляется при наличии параметра `date` в URL и позволяет вернуться к текущей дате

## Интерфейс страницы Options

### Внешний вид

### Options, Секция "Habits Management"

Каждая привычка в списке отображается в отдельной строке с:
 - Названием привычки слева
 - Блок кнопок справа (выровнен по правому краю)

Блок кнопок для каждой привычки содержит:

- Удаление привычки: подтверждение через диалог ("Вы уверенны? Да/Нет")
- Перемещение привычек: мгновенное обновление порядка

# Архитектура проекта

## Обзор структуры

Проект представляет собой веб-приложение для отслеживания привычек. Основная архитектура включает:

1. **Бэкенд на Python (Flask)**:
   - `habits_database.py` - класс HabitsDatabase для работы с SQLite базой данных
   - `flask_backend_core.py` - API-эндпоинты Flask и основная логика сервера
   - `habits_core.py` - бизнес-логика для работы с привычками

2. **Фронтенд (HTML/JavaScript)**:
   - `templates/` - HTML шаблоны (Jinja2)
     - `index.html` - главная страница с таблицей привычек
     - `habit.html` - страница отдельной привычки
     - `habit_options.html` - страница настроек привычки
     - `options.html` - страница глобальных настроек
     - `constants.js` - шаблон для генерации JavaScript констант
   - `static/` - статические файлы
     - `script.js` - основной JavaScript для интерфейса трекера привычек
     - `habit.js` - JavaScript для страницы отдельной привычки
     - `menu.js` - JavaScript для плавающего меню
     - `notifications.js` - JavaScript для уведомлений
     - `options_habit_edit.js` - JavaScript для страницы редактирования привычки
     - `style.css` - стили приложения

## API-эндпоинты

Приложение предоставляет следующие основные API-эндпоинты:

- `/api/habits` - получение данных о привычках
- `/api/habits/update` - обновление статуса привычки
- `/api/habits/add` - добавление новой привычки
- `/api/habits/delete` - удаление привычки
- `/api/habits/list` - список всех привычек
- `/api/habits/rename` - переименование привычки
- `/api/habits/export` - экспорт привычек в CSV
- `/api/habits/import` - импорт привычек из CSV
- `/api/param/<name>` - получение/установка глобального параметра
- `/api/param/<name>/<id>` - получение/установка параметра привычки
- `/api/main_page` - получение данных для главной страницы

## База данных

База данных SQLite содержит следующие таблицы:
- `habits_list` - список привычек
  - `id` - идентификатор привычки
  - `name` - название привычки
  - `sequence` - порядковый номер для сортировки привычек
- `habit_tracking` - данные отслеживания привычек по дням
  - `habit_id` - идентификатор привычки
  - `date` - дата в формате 'YYYY-MM-DD'
  - `status` - статус привычки на указанную дату
- `habit_params` - параметры привычек и глобальные параметры
  - `habit_id` - идентификатор привычки (-1 для глобальных параметров)
  - `param_name` - имя параметра
  - `value` - значение параметра (хранится как строка)

## Ключевые механизмы

1. **Параметры привычек**:
   - Система хранения параметров привычек через механизм `get_param` и `set_param`

   - Параметры привычек:
     - `fail_by_default` - привычка считается проваленной, если не отмечена как выполненная
     - `single_checkbox` - ограничивает статусы только тремя (не отмечено, выполнено, провалено)
     - `multi_numbers` - ограничивает доступные статусы только числовыми значениями (0 и 10-19)
     - `bad_habit` - для негативных привычек (инвертирует цвета статусов)

   - Глобальные параметры:
     - `theme` - тема интерфейса (в разработке)
     - `test_option` - тестовый параметр

  - `VALID_HABIT_PARAMS` - Список допустимых параметров для привычек (для каждой привычки по отдельности)
  - `VALID_GLOBAL_PARAMS` - Список допустимых глобавльных параметров для базы данных

2. **Сортировка привычек**:
   - Привычки сортируются по полю `sequence` (порядковый номер)
   - При равных значениях `sequence` используется сортировка по `id`
   - Метод `set_habit_sequence` позволяет установить порядковый номер для привычки
   - При экспорте/импорте порядок привычек сохраняется

3. **Статусы привычек**:
   - Каждая привычка имеет несколько возможных статусов (0-9)
   - Функция `status_mapping` преобразует внутренние значения статусов в соответствии с параметрами привычки
   - Основные статусы:
     - 0 - не установлено
     - 1 - минимально выполнено
     - 2 - выполнено
     - 3 - элитно выполнено (с дополнительной анимацией)
     - 9 - провалено
     - 10-19 - числовые статусы (отображаются как 0-9)
   - Для привычек с параметром `bad_habit` цвета статусов инвертируются:
     - Положительные статусы (done mini, done, done elite) отображаются красным
     - Отрицательные статусы (fail) отображаются зеленым
     - Числовые статусы (10-19) отображаются красным, кроме 0 (синий)

4. **Циклическое переключение статусов**:
   - При клике на ячейку статусы циклически меняются (0 -> 1 -> 2 -> 3 -> 9 -> 0)
   - При двойном клике появляется контекстное меню со всеми возможными статусами
   - Опция `single_checkbox` ограничивает доступные статусы только тремя: не установлено (0), выполнено (2) и провалено (9)
   - Опция `multi_numbers` ограничивает доступные статусы только числовыми значениями: не установлено (0) и числа (10-19, отображаются как 0-9)

5. **Рендеринг интерфейса**:
   - Данные загружаются через API-эндпоинт `/api/main_page`
   - Функция `fetchHabitsData` получает данные и сохраняет их в глобальной переменной `habitsData`
   - Функция `renderTable` отрисовывает таблицу привычек
   - Функция `getStatusOptions` возвращает список доступных статусов (с фильтрацией по `single_checkbox`)

6. **Обработка событий**:
   - `handleCellClick` - обработчик клика на ячейку (циклическое переключение статуса)
   - `handleCellDblClick` - обработчик двойного клика на ячейку (показ меню статусов)
   - `sendUpdate` - отправка обновления статуса на сервер
   - Система откладывает отправку обновлений для уменьшения нагрузки на сервер

# Заметки

## Технические заметки

- Параметры хранятся в таблице `habit_params` как строки

- Параметр `single_checkbox` добавляется в данные привычки при отправке через API
  Это позволяет фронтенду учитывать особенности отображения без дополнительных запросов

- Для статусов привычек важен как внутренний код (0-9), так и отображаемое значение,
  которое определяется функцией `getStatusEmoji` на фронтенде и методом `status_mapping` на бэкенде

## `constants.js` - константы для фронтенда

- `constants.js` - это не обычный JavaScript файл, а шаблон Jinja2, который генерируется сервером
- Файл содержит константы, которые редко меняются, что позволяет их кешировать на стороне клиента
- Эндпоинт `/js/constants.js` генерирует этот файл с помощью функции `prepare_js_constants`
- В constants.js определяется функция `getStatusOptions()`, которая возвращает список возможных статусов
- Файл настроен с заголовками кеширования (`Cache-Control`), чтобы уменьшить количество запросов к серверу
- Константы включают:
  - `tableDaysCount` - количество дней, отображаемых в таблице привычек
  - `approximateHabitsCount` - приблизительное количество привычек для предварительного рендеринга строк таблицы
  - `weekDays` - массив названий дней недели для отображения в заголовках таблицы

## Оптимизации

- Система предварительно рендерит пустые строки таблицы для ускорения загрузки страницы
- Кеширование `constants.js` уменьшает количество запросов к серверу
- Отложенная отправка обновлений статусов уменьшает нагрузку на сервер

## Смещение даты в главной таблице

- Для отображения привычек за другую дату можно использовать параметр `?date=YYYY-MM-DD` в URL
- Если параметр `date` присутствует, автоматически добавляется кнопка "Today" рядом с иконкой настроек
- Функция `calculateDateRange()` проверяет наличие параметра `date` и использует его как базовую дату для расчета диапазона
- При нажатии на кнопку "Today" происходит возврат к текущей дате (удаление параметра `date` из URL)
- Кнопка "Today" добавляется динамически через JavaScript только при необходимости
- Кнопка имеет стили класса `option-button` для единообразного отображения

## Страница отдельной привычки

- Таблица календарей теперь имеет квадратные ячейки (32x32 пикселя)
- Календари выровнены по левому краю экрана
- Функция `renderMonth` всегда создает 6 строк в календаре, чтобы оба месяца имели одинаковую высоту
- Пустые ячейки имеют класс `empty` с соответствующими стилями
